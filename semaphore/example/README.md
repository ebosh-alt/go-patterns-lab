# Реализация Semaphore на Go

Каталог содержит три самостоятельные версии семафора. Они показывают, как меняется реализация при добавлении отмены и разного веса операций.

| Версия | Что показывает | Ограничение |
|---|---|---|
| [`basic`](basic/) | Считающий семафор на `chan struct{}` | Ожидание нельзя отменить |
| [`context`](context/) | Захват разрешения через `context.Context` | Все операции имеют одинаковый вес |
| [`weighted`](weighted/) | Разный вес операций и общая ёмкость | Нет отмены ожидающего захвата |

## Basic

Буферизованный канал хранит занятые разрешения. Его ёмкость равна максимальному числу одновременных операций.

`Acquire` отправляет пустую структуру в канал. Если буфер заполнен, горутина блокируется. `Release` читает значение из канала и освобождает место.

Пример запускает восемь задач при лимите два и показывает, что одновременно работают не больше двух.

```bash
go run ./semaphore/example/basic
```

## Context

Эта версия добавляет отменяемое ожидание.

`Acquire` использует `select`: либо захватывает свободное разрешение, либо возвращает ошибку `ctx.Err()`. `Release` вызывается только после успешного захвата.

Пример удерживает единственное разрешение дольше дедлайна второй операции. Ожидающая операция завершается по timeout, а после освобождения места следующий захват снова становится возможен.

```bash
go run ./semaphore/example/context
```

## Weighted

Взвешенный семафор хранит общую ёмкость и занятый вес.

`Acquire(weight)` ждёт, пока сумма занятого веса и нового запроса не поместится в лимит. `Release(weight)` возвращает ровно тот же вес и будит ожидающих участников.

Реализация использует `sync.Cond`, потому что одна операция должна атомарно захватывать несколько разрешений. Последовательная отправка нескольких значений в канал может занять часть веса и заблокировать остальные операции.

```bash
go run ./semaphore/example/weighted
```

## Тестирование

Из корня репозитория:

```bash
go test -count=1 ./semaphore/example/...
go test -race ./semaphore/example/...
```

Тесты проверяют:

- максимальное число одновременных операций;
- отмену ожидающего `Acquire`;
- повторное использование разрешения после `Release`;
- ограничение суммарного веса.
