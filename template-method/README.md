# Паттерн Шаблонный метод

> Также известен как Template Method. Является поведенческим паттерном проектирования.

___

## Идея

Зафиксировать общий порядок шагов алгоритма и разрешить отдельным реализациям менять только детали этих шагов.

Например, одноразовый код можно отправить по SMS или email. В обоих случаях нужно создать код, сохранить его, подготовить сообщение и отправить. Порядок остаётся одинаковым, а реализация отдельных шагов зависит от канала доставки.

___

## Когда применять

- Есть несколько алгоритмов с одинаковой последовательностью шагов
- Общую логику нужно хранить в одном месте
- Конкретные реализации должны изменять отдельные этапы, но не весь алгоритм
- Нужно контролировать порядок выполнения операций

___

## Плюсы

- Устраняет дублирование общей части алгоритма
- Фиксирует правильный порядок выполнения шагов
- Позволяет добавлять новые варианты через отдельные реализации
- Упрощает тестирование общего сценария

___

## Минусы

- Жёсткая последовательность может усложнить нестандартные варианты алгоритма
- Большое количество изменяемых шагов делает контракт сложным
- В языках без наследования требуется адаптировать классическую структуру через интерфейсы и композицию

___

## Структура

- **AbstractClass** содержит шаблонный метод и объявляет отдельные шаги алгоритма
- **Template Method** вызывает шаги в заданном порядке
- **ConcreteClass** реализует изменяемые шаги
- **Client** выбирает конкретную реализацию и запускает шаблонный метод

![](/img/structure-template-method.png)

Сам шаблонный метод не должен зависеть от деталей конкретной реализации.

___

## Варианты и приёмы

- Базовые шаги могут иметь реализацию по умолчанию
- Hooks позволяют добавить необязательные точки расширения
- Часть шагов можно передавать как стратегии
- Фабричный метод можно использовать для создания зависимостей внутри отдельных шагов

___

## Типичные ошибки

- Изменение порядка шагов в конкретной реализации
- Слишком большое количество точек расширения
- Зависимость шаблонного метода от конкретного класса
- Использование паттерна для алгоритмов, у которых почти нет общей структуры

___

## Где хорошо ложится

- Импорт и экспорт данных
- Конвейеры обработки
- Жизненные циклы объектов
- Парсеры и рендеры
- Генераторы отчётов

___

**Формула:** зафиксировать общие шаги и менять только детали.
