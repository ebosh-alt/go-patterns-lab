# Реализация Worker Pool на Go

В каталоге находятся три самостоятельные версии одного паттерна. Они показывают, какие элементы появляются по мере роста требований к пулу.

| Версия | Что показывает | Когда полезна |
|---|---|---|
| [`basic`](basic/) | Канал задач, фиксированные воркеры, `sync.WaitGroup` | Нужно понять механику паттерна |
| [`context`](context/) | Ограниченная очередь, отмена, ошибки и graceful shutdown | Задачи зависят от внешнего запроса или могут завершаться с ошибкой |
| [`generic`](generic/) | Типизированные входы и результаты | Один механизм должен обрабатывать разные типы без `interface{}` |

## Basic

Минимальная версия принимает функции без аргументов через канал `tasks`.

Конструктор запускает фиксированное число горутин. Каждая горутина читает общий канал, выполняет задачу и ждёт следующую. Метод `Close` закрывает очередь и ждёт выхода всех воркеров.

Эта версия намеренно не содержит context, результатов и отдельной обработки ошибок. Она показывает базовый жизненный цикл пула без дополнительных состояний.

Запуск:

```bash
go run ./worker-pool/example/basic
```

## Context

Практическая версия принимает функции вида `func(context.Context) error`.

В ней появляются:

- буферизованная очередь ограниченного размера;
- отмена через `context.Context`;
- канал результатов задач;
- graceful shutdown с завершением уже принятых задач;
- отдельный метод немедленной отмены.

`Submit` возвращает ошибку, если context пула уже отменён. `Close` закрывает очередь и ждёт её обработки. `Cancel` посылает сигнал отмены и позволяет задачам прекратить работу через `ctx.Done()`.

Методы `Submit`, `Close` и `Cancel` в учебной реализации вызываются координатором последовательно. Одновременная отправка и закрытие очереди не поддерживаются.

Запуск:

```bash
go run ./worker-pool/example/context
```

## Generic

Типизированная версия отделяет входные данные от функции обработки:

- `Process[I, O]` преобразует значение типа `I` в значение типа `O`;
- `Submit` принимает только входные данные;
- `Results` возвращает исходное значение, результат и ошибку;
- `Close` прекращает приём задач и закрывает канал результатов после выхода воркеров.

Порядок результатов не гарантирован, потому что задачи выполняются параллельно.

Запуск:

```bash
go run ./worker-pool/example/generic
```

## Тестирование

Из корня репозитория:

```bash
go test -count=1 ./worker-pool/example/...
go test -race ./worker-pool/example/...
```

Тесты проверяют:

- выполнение всех отправленных задач;
- доставку ошибок;
- реакцию задачи на отмену context;
- получение типизированных результатов.
