# Паттерн Команда

> Также известен как: Command. Является поведенческим паттерном проектирования.

___

## Идея

Команда заворачивает запрос в отдельный объект. Отправитель знает только, что у команды есть метод `Execute`, а получатель хранит настоящую бизнес-логику.

Так можно назначать действия элементам интерфейса, складывать их в очередь, сохранять историю и реализовывать отмену через обратные команды или снимки состояния.

___

## Когда применять

- Несколько элементов интерфейса должны запускать одно действие.
- Действия нужно ставить в очередь или выполнять по расписанию.
- Нужны история операций, повтор или отмена.
- Логику вызова нужно отделить от бизнес-логики получателя.

## Плюсы

- Слабая связанность между UI и бизнес-логикой.
- Одну команду можно передать разным отправителям.
- Очередь, логирование и история команд не требуют менять получатель.
- Конкретные действия легко тестировать отдельно.

___

## Минусы

- Для каждого действия появляются дополнительные типы.
- Отмена не возникает автоматически: команда должна уметь хранить предыдущее состояние или иметь обратную операцию.
- Для совсем простого вызова абстракция может быть избыточной.

___

## Где хорошо ложится

- Кнопки, горячие клавиши и пункты меню.
- Очереди фоновых задач.
- Транзакционные операции с undo/redo.
- Макросы и пакетное выполнение действий.

___
